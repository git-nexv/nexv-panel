# bwtest — تست پهنای باند به سرور

یک ابزار سبک و بدون هیچ وابستگی (فقط Node.js نسخه ۱۸ به بالا) برای اندازه‌گیری
پهنای باند واقعی بین سیستم خودت و سرورت — در هر دو جهت. بر خلاف تست‌های سرعت
مرورگر که مسیر تا نودِ یک شرکت دیگر را می‌سنجند، این ابزار دقیقاً مسیر تا
**سرور خودت** را با چند اتصال موازی TCP پر می‌کند (همان ایده‌ی iperf، اما در یک
فایل که هرجا Node باشد اجرا می‌شود).

## چطور کار می‌کند

دو طرف دارد و هر دو طرف همین یک فایل هستند:

۱) روی سرورت (همان IP که می‌خواهی تست کنی) این را اجرا کن:

```bash
node bwtest.js server
```

پیش‌فرض روی پورت `5201/TCP` گوش می‌دهد. اگر فایروال داری، این پورت را باز کن
(یا با `--port` پورت دیگری بده).

۲) روی سیستم خودت این را اجرا کن:

```bash
node bwtest.js client <IP-سرور>
```

مثال:

```bash
node bwtest.js client 203.0.113.10 -t 15 -s 8
```

کلاینت اول **دانلود** (سرور → تو) و بعد **آپلود** (تو → سرور) را تست می‌کند و در
پایان اوج و میانگین هر جهت را می‌دهد.

## گزینه‌ها

| گزینه | معنی | پیش‌فرض |
|---|---|---|
| `--port`, `-p` | پورت سرور | `5201` |
| `--time`, `-t` | مدت هر جهت (ثانیه) | `10` |
| `--streams`, `-s` | تعداد اتصال موازی | `4` |
| `--down` | فقط تست دانلود | — |
| `--up` | فقط تست آپلود / ورودی سرور | — |
| `--both` | هر دو جهت | (پیش‌فرض) |

برای خطوط پرسرعت (مثلاً بالای ۱ گیگابیت) تعداد اتصال‌ها را بیشتر کن، مثل `-s 8`
یا `-s 16`، چون یک اتصال تکی به‌خاطر تأخیر و اندازه‌ی پنجره‌ی TCP معمولاً کل خط
را پر نمی‌کند.

## عدد «ورودی سرور»

عددی که واقعاً نشان می‌دهد سرورت حداکثر چقدر ترافیک **می‌گیرد**، همان
**میانگین آپلود** است. این عدد را خودِ سرور می‌شمارد (نه کلاینت) و برمی‌گرداند،
پس قابل اعتماد است.

نتیجه را با پهنای باندی که سرویس‌دهنده‌ات قول داده مقایسه کن؛ اگر خیلی کمتر بود،
یعنی پهنای باند کامل بهت تحویل داده نمی‌شود.

## نکته

- ترافیک این تست واقعی است و از مصرف پهنای باند/حجم سرورت کم می‌کند؛ برای همین
  مدت را کوتاه نگه دار.
- اگر کلاینت نتوانست وصل شود، مطمئن شو سمت سرور `node bwtest.js server` در حال
  اجراست و پورت در فایروال باز است.
